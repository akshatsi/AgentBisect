# Decisions

One line per non-obvious choice: date, decision, reason.

- 2026-10-26 · Step indices are 1-based; step 0 is the base snapshot. `Trace.snapshot_at(i)` falls back to the latest earlier snapshot, so read-only steps need none.
- 2026-10-26 · A run on disk is `meta.json` + `trace.jsonl` (one `Step` per line), so traces stream and append cleanly.
- 2026-10-26 · Ruff ignores E501 (the formatter owns line length) and B008 (typer's `Option()` defaults).
- 2026-10-26 · Flaky oracle: a sequential ±d test with an odd run cap, per-decision error budget 0.05 / (⌈log₂ n⌉ + 2). See METHODS §2.
- 2026-10-26 · Deterministic oracle is assumed when 6 calibration runs all agree, then the boundary gets 3 fresh runs on each side; any disagreement switches to the flaky path. One run per probe in the common case.
- 2026-10-26 · Pytest exit 2 (collection error, e.g. a syntax error the agent wrote) counts as FAIL, not ERROR, since it is the most common way agents break code.
- 2026-10-26 · In a non-monotone history the decisive step is the last pass→fail transition (the break the final state still carries). AGENTS.md glossary left as written; this refines it.
- 2026-10-26 · Snapshots exclude `.git`, `__pycache__`, `*.pyc`, tool caches, `.venv`, `node_modules`: they never affect test results but would make identical states look different. Dedup is by tree hash across the whole history, so a reverted edit reuses the earlier snapshot SHA.
- 2026-10-26 · The oracle runs with `PYTEST_ADDOPTS=--rootdir=<scratch>` and the venv's bin dir first on PATH, so a project config above `runs/` (this repo's own `pyproject.toml`) cannot leak into the check.
- 2026-10-26 · `bisect()` takes an optional `executor` (sha -> OracleRun) so tests simulate flaky oracles with no subprocess. Real runs never use it.
- 2026-10-26 · `analyze.py` follows METHODS §4 with three tightenings: a key must stand alone in the line (`test_f` does not match `test_f2`), the P2 header uses the class-qualified name when the node ID has a class, and a check that names no test or file (the whole suite) accepts any `FAILED`/`ERROR <id>` line or pytest failure header. Without the last rule a `--check "pytest -q"` run would be censored every time. math-analyst should confirm.
- 2026-10-26 · Auto-oracle runs `python -m pytest -q -rA --continue-on-collection-errors` at step 0 and step n and parses the `-rA` summary. A test that passes at 0 and is FAILED/ERROR at n is bisected with `python -m pytest -q <node id>`; a file that no longer collects takes its passing tests with it; a test missing at n (deleted) is not a failure.
- 2026-10-26 · `bisect_run` returns no culprits when nothing newly fails, and one not-bisectable culprit (check = `python -m pytest -q`) when the suite itself cannot run (exit 127/5/4/3 or timeout at step 0 or n). `RunReport` has no message field, so the CLI words the empty case.
- 2026-10-26 · Not-bisectable reasons name the cause: exit 127 (command not found), 126, pytest 5 (no tests matched), 4 (test ID not found or usage error), 3 (internal error), or timeout with the limit. The prefix `oracle error at step N:` stays.
- 2026-10-26 · Alan AI has no API-key access, so the agent under test is Alan Code (OpenCode bundled in the Alan app, open models via Alan). A project plugin in the task folder records every tool call and snapshots the repo. Our own harness on `llm.py` stays as a backup for any OpenAI-compatible endpoint. Checked: OpenCode 1.19.3 loads `<project>/.opencode/plugin/*.js`.
- 2026-10-26 · Because runs are started by hand and billed to the human's Alan account, the study shrinks to about 16–20 runs (design in METHODS §8). The `ALAN_SPEND_CAP_USD` cap applies only to the backup harness.
- 2026-10-26 · Snapshots also exclude `.opencode/` (the Alan Code recorder plugin lives at `<workdir>/.opencode/plugin/agentbisect.js`), so it never shows in snapshots, diffs, tree dedup or the oracle scratch tree.
- 2026-10-26 · `bisect`, `bisect_run`, `analyze` and `Oracle` resolve `run_dir` (and the scratch dir) to absolute paths on entry: a relative path was resolved a second time inside the check's shell, so pytest looked in the wrong directory.
- 2026-10-26 · Claude Code hook registers `PostToolUseFailure` too: a Bash command with non-zero exit (a failing pytest) fires only that event, so without it no failure output is recorded. Base snapshot comes from `SessionStart`.
- 2026-10-26 · Tokens of one model request go to its first tool call only, in every recorder. `tokens_in` includes cache read and write.
- 2026-10-26 · Alan Code runs fall back to rebuilding steps from `events.jsonl` with one final snapshot if `tool.execute.after` never fires. Such runs are smoke tests, not study data. `agentbisect run` finalizes an Alan Code run first, in case the agent never went idle.
- 2026-10-26 · `record()` re-raises `SpendCapExceeded` after saving the partial trace, so a batch stops when the cap is hit.
- 2026-10-26 · Each Alan Code workdir gets its own git repo with one commit. The first real run showed the agent running `git status`, which walked up into the user's project repo. Snapshots exclude `.git`.
- 2026-10-26 · First real Alan Code run (t01, DeepSeek V4.1 Flash): per-call hooks fire, 21 steps each with a snapshot. Alan's events report cost 0, so cost per run is read from the Alan usage page, not the trace. One run used about 460k tokens, mostly re-sent context.
- 2026-10-26 · A run where Alan resumed an earlier conversation (`<resume_context>` in the events) is flagged in `finalize.json` and by `agentbisect run`, and is excluded from the study. The first t04 run was discarded for this reason.
- 2026-10-26 · Only DeepSeek models are usable in Alan Code, so the cross-model comparison narrows to DeepSeek (METHODS §8).
- 2026-10-26 · study.py: a run is study data only if it is a finished, non-resumed, per-step-snapshot Alan Code run of a `flash` model and its directory is not `x-*`; every other directory with no `meta.json` or a different reason lands in `StudySummary.excluded`, keyed by directory name. Rows use the directory name as `run_id`.
- 2026-10-26 · study.py: `bisect.json` is reused only if it came from the auto-oracle (`auto_oracle` true); a hand-picked `--check` report is redone. `collect` finalizes runs that have `events.jsonl` first, as `agentbisect run` does.
- 2026-10-26 · study.py: a run whose suite cannot run (not-bisectable culprit with check `python -m pytest -q`) gets `final_failed=True, bisectable=False`; a run with no culprit gets `final_failed=False`. Sabotage runs (`meta.sabotage_step` set) are out of the broken-run share and all lag statistics; sabotage accuracy counts a run as right if any FOUND culprit has `t_err == sabotage_step`.
- 2026-10-26 · study.py episodes (METHODS §8.4, simplest reading): per test that passes at step 0 (one `-rA` suite run at the base, only if some pytest step failed), walk the agent's pytest runs in order. A §4.2 signal for the test (its own node ID, no touched files) starts an episode unless the test was already failing at the previous run that covered it; a covering run with no signal ends the streak. Coverage is read from the command's path arguments (`-k`, `-m`, `--lf` mean partial).
- 2026-10-26 · study.py episodes: when the agent saw the test pass earlier (a repaired break), bisect runs over the steps after that last pass instead of `0..k`, because plain bisect on a non-monotone `0..k` can stop on the old, repaired break. If the oracle does not pass at that step, it falls back to `0..k`. Otherwise `0..k` as in §8.4. Sabotage runs contribute no episodes (METHODS §8.4 audit).
- 2026-10-26 · study.py: the repaired-break lag CI is a bootstrap over the runs that have at least one episode (a resample with no episode has no median). The wasted-token CI resamples tasks, as §8.3 says. Bisected episodes are cached in `runs/study/cache/<run>.episodes.json`, keyed by the trace content; `rebisect=True` redoes them.
- 2026-10-26 · study.py (§8.4 audit): a run whose whole suite cannot run at step 0 is excluded as an environment fault (reason starts `full suite could not run at step 0` or `oracle error at step 0`); only at step n it stays as broken, not bisectable. Added the "Noticed at once (lag 0)" metric, 1 - S(0), as a Wilson share of primary broken runs.
- 2026-10-26 · Study order changed after 4 green runs: s03 (sabotage) moved ahead of t04 to get a real broken trace early. Noted here and to be stated in RESULTS.md.
- 2026-10-26 · Oracle env for bring-your-own-repo: `meta.python`'s bin dir leads PATH (not resolved, a venv python is a symlink), `VIRTUAL_ENV` follows it, `PYTHONHOME` is cleared, and `PYTHONPATH` starts with `<scratch>` and `<scratch>/src` so a non-editable install in the venv can never shadow the snapshot's code. A missing `meta.python` is "not bisectable: project venv missing at <path>".
- 2026-10-26 · Auto-oracle bisects at most `MAX_AUTO_CULPRITS = 10` newly failing tests, sorted by node ID; the rest appear in `RunReport.checks` as `<check>  (not bisected: cap)` with no culprit, so a real project with many failures stays affordable.
- 2026-10-26 · Own-repo runs: the project's venv lives at `runs/<id>/venv`, outside the workdir, so it is never snapshotted. The recorder plugin keeps AgentBisect's interpreter; `meta.python` holds the project's. A failed project build falls back to installing its declared dependencies only.
- 2026-10-26 · Local `.env`, `.env.local` and `.env.*.local` files are not copied into the workdir, since the workdir is snapshotted and shown in reports.
- 2026-10-26 · bisect.py now owns episode detection (`find_episodes`, moved from study.py; study imports it). `bisect_run` fills `RunReport.repaired` for every run, auto-oracle or explicit check, sabotage runs included, so a run that ends green still names the step that broke the code and the agent saw and fixed (real run s03: break at 9, seen at 13, reverted at 18). A report lists an episode only if the agent later saw the test pass, or the test passes at the final step (auto-oracle: not in the newly failing set; explicit check: one extra suite run at step n). Breaks still live at the end stay in `culprits`. The study keeps all seen episodes, repaired or not, as before.
- 2026-10-26 · study.py: sabotage runs now get episodes too (the early return is gone); `summarize` still drops them from the repaired-break lag series. Sabotage accuracy counts a run as right if a final-state culprit OR an episode has `t_err == sabotage_step` (the break was live where the agent saw it). The rated runs are those that fail at the end or have any episode, so a sabotage run the agent saw and fixed now counts. The episode cache key gained a version salt, so old caches (which held no sabotage episodes) are redone.
- 2026-10-26 · Own-repo projects are installed editable, so the agent's own pytest runs import its working copy. The oracle is unaffected: the scratch tree comes first on `PYTHONPATH`. Checked on humanize: with the working copy broken, bisect still found the planted step.
- 2026-10-26 · Snapshots ignore the project's own `.gitignore` (`git add --force` with our exclude pathspecs). humanize's build-time `_version.py` is gitignored, and without it every restored snapshot failed to import. Build output (`build/`, `dist/`, `*.egg-info/`, `.tox/`) is now in our own excludes.
- 2026-10-26 · The recorder plugin folder `.opencode/` is in the workdir's local `.git/info/exclude`, so the agent's `git status` does not show it.
- 2026-10-26 · Terminal color codes are stripped before parsing pytest results and matching failure signals. humanize sets `--color=yes`, which hid every result line from the auto-oracle.
- 2026-10-26 · `record --repo` takes `--sabotage FILE` (YAML: at_step, file, find, replace) to plant a known break in a real project, checked to occur exactly once before the run starts.
- 2026-10-26 · analyze.py (METHODS §4.2): a "piped pytest" step is one whose first pytest call (`pytest`, `py.test`, `-m pytest`, found by splitting the command on `&&`, `||`, `;`, `|` and newlines, quotes respected) ends in a lone `|`. The program must be pytest itself, so `grep pytest log | tail` does not count, and `pipefail` anywhere in the command turns the rule off. With exit 0 such a step shows a signal only through P1, P1b, P2, P3. P1b is `^ERROR \S*(?<![\w.-])<file>(?!::)\b`; the lookbehind keeps `my_test_x.py` from matching `test_x.py`. `_line_matches` strips colors itself, so no caller can forget.
- 2026-10-26 · bisect.py episodes: a piped pytest run with no failure signal ends a streak (the agent saw the test pass) only if its output has a `N passed` summary and no `N failed` / `N errors`. `pytest | tail -3` can cut off the failure list, so a missing signal there is not evidence of a pass. Unpiped runs are unchanged (the exit code backs the missing signal).
- 2026-10-26 · analyze.py (METHODS §4.4) manager's ruling, beyond the §4.4 text: a planted break at `t_err == meta.sabotage_step == n` is `no_opportunity` even when step n is a shell step. The planted edit is applied after the step's tool ran, so that step's output cannot show it. An organic break on a shell last step keeps the normal rule (lag 0 if the output shows it). The flag forces `t_obs = None`, `censored = True`, `steps_after_err = 0`. Note that `make_synthetic_run` always sets `meta.sabotage_step`, so tests of organic behavior reset it to None.
- 2026-10-26 · study.py: `StudyRow.no_opportunity` is copied from the analysis. `summarize` takes the primary row per run as before and then drops no-opportunity rows from the censoring rate, "Noticed at once", the KM median and both wasted-token metrics; they stay in the broken-run share, the bisectable share and sabotage accuracy. New count metric "No opportunity to observe (break on last step)" counts task runs, and its note gives the number of sabotage runs with the flag.
- 2026-10-26 · Study scope: agent-behavior metrics use practice-repo task runs only. Own-repo runs without a planted break (humanize) are case studies and excluded with a reason. Planted breaks from any repo count toward sabotage accuracy, which measures the bisector, not the agent.
- 2026-10-27 · Report pages are Preact 10.29.8 + htm 3.1.1 apps, vendored in `agentbisect/report/assets/vendor/` and inlined into one file (versions and licences in `assets/LICENSES.md`). Preact 11 ships ES modules only, which cannot run from a plain inline script, so we use the last 10.x. htm is Apache-2.0, not MIT; its licence text is kept next to it.
- 2026-10-27 · Report data is one `<script type="application/json" id="data">` blob with `<`, `>`, `&` and every non-ASCII character written as `\uXXXX`, so no run text can close the script or open a comment. The apps draw run text through text nodes only (no `innerHTML`). `page.py` edits the vendored scripts when it inlines them: it drops the source-map comment and writes the `http://` of the namespace strings as `http:\/\/` (the same JavaScript string), so a built page holds no `http://` outside the data.
- 2026-10-27 · The bisect replay is computed in Python from the stored probe log. After each probe the unknown interval widens over neighbouring steps with the same snapshot (a step that changed no file shares the state before it), so the last frame lands on `[t_err - 1, t_err]`. A non-monotone history gets no shaded interval; its probes are shown one by one.
- 2026-10-27 · A repaired break stores no probe log, so its replay is a reconstruction: the probes a binary search over steps `0..seen_at` makes when the answer is the known `t_err`. The page labels it "reconstructed" and says nothing was re-run.
- 2026-10-27 · Each mutating step carries its own diff (snapshot after versus snapshot before), cut at 20 KB (60 KB for the steps a verdict names); all diffs together stay under 1.2 MB, and steps past that keep their text but show "diff left out". Step output is ANSI-stripped and clipped head-and-tail (the end of a pytest run is the useful part).
- 2026-10-27 · The "AI explanation" label and its note travel in the data next to the model's text, never in the page script, so a page with no explanation holds neither.
- 2026-10-27 · The study page's demo cards are the hand-named runs next to `study/`: ids not ending in `-YYYYMMDD-HHMMSS` and not starting with `x-`, with a trace and a `report.html`, either counted or excluded as case studies. At most 3, culprit first. `render_study` shows none unless the caller passes `linkable`.
- 2026-10-27 · Reports and the study page use one dark theme (near-black gray, white text, red and green for fail and pass, amber for steps on broken code) with solid colors only: no gradients, no light/dark switch. README screenshots retaken.
- 2026-10-27 · The study page has a 'Try it on your own repo' panel: a static command builder (nothing is executed, no server). Values are single-quoted and prompts go through heredocs with a unique quoted delimiter, so any text survives the shell. URL schemes are written with escaped slashes in the script to keep the page's no-network check.
- 2026-10-27 · Scope exception approved by the human: `agentbisect serve`, a local web app (fifth command) with a form that clones a repo, installs it, records, bisects and shows the report. `AGENTS.md` still says "no web server, four commands"; this overrides it for `serve` only. It needs no new dependency (standard-library HTTP server). It runs code (git clone, dependency install, pytest), so it binds to 127.0.0.1 only, requires a per-process token, checks Host and Origin, and accepts only https://, file:// or a local path. It cannot start the agent: that step stays manual in the Alan app.
- 2026-10-27 · Local app page (`report/serve_page.py`): one offline Preact page that reads the token from `#token=`, removes it from the address, and sends it as `X-AgentBisect-Token` on same-origin `/api/` calls. The run form, Copy button and Field moved from the study page into `assets/runform.js`, so both pages share them. Job polling is 1 s; a test sets `window.AB_POLL_MS` to go faster. Verdict chip tone is read from the verdict text (the API sends no tone): red unless the text says fixed/caught/no failing check (green) or not bisectable (amber).
- 2026-10-27 · The README screenshot of the local app is taken from the real server with the real demo runs. A first screenshot used stub data (runs we never made) and was replaced.
- 2026-10-27 · The demo video is generated, not screen-recorded: docs/demo/make_video.py renders the real pages and the real terminal output with headless Chrome, adds a macOS `say` voiceover, and joins them with ffmpeg. It says plainly that the break on python-humanize was planted.

The voice is Kokoro (local neural TTS) instead of macOS say. It runs in a throwaway `uv run --no-project` environment so the project's dependencies and .venv stay as they are. Supersedes the earlier note about a stills-and-say video.
